## 2. Conflicts and how they're resolved

1. **`/` already holds real product UI** (Home). Owner decision, 2026-10-15: build the landing at **`/welcome`**, keep Home at `/`, and swap once the L3 handoff to `/study` works. The swap is one move (`app/welcome/page.tsx` → `app/page.tsx`) plus a new home for Home's recent-lessons list (open question 1). Until then, links inside the landing that say "home" point at `/welcome`.
2. **`lib/landing.ts` already exists.** It is the workspace's "block landed below" chip logic, unrelated to this page. The new modules live in the directory `lib/landing/` next to it. `@/lib/landing` keeps resolving to the old file, and new code imports full paths (`@/lib/landing/film-schedule`). Renaming the old file (for example to `lib/block-landing.ts`) would be tidier; it's left alone because it isn't this work's file.
3. **`DirectorLine` is called `StreamLine` here, and a working inference path already exists.** The prompt's `lib/inference/*` is "only if the repo has none", so **no `lib/inference/` is created**. The landing calls no inference at all, and `/study` keeps using `sendTurn`, which is real or mock depending on `MOCK_LLM`. L3's check "the placeholder inference reply renders" becomes "the existing pipeline replies (run with `MOCK_LLM=1`)". The dev badge reads `auth: placeholder` only.
4. **The handoff needs to prefill a composer whose text is local state, in three possible places.** Plan for L3: `lib/landing/handoff.ts` stores the pending handoff; `/study` reads it (URL first, then sessionStorage), clears both, and exposes it through a tiny zustand slice that every `Composer` reads once on mount to prefill, focus and show the hint. On the first send while the handoff is pending, it calls `startLesson(q, level)` then `sendTurn`, exactly like `Home.start`. No contract changes, never auto-sends.
5. **Themes.** The app has paper, sepia and ink. The film, placard, login card and final frame use the prompt's fixed paper and ink values (they sit on plates, so they can't follow the theme). Starting points, the footer and the sticky header use tokens, so they follow the learner's theme. Open question 2.
6. **Confidence words.** The prompt's links say `established` / `likely` / `contested`; the contracts say `E` / `L` / `C`. The content keeps the prompt's words, and one map in `lib/landing/types.ts` converts them, so arcs use the same visual language as cause graphs.
7. **The ticker can't use plain 2-significant-figure rounding.** Rounding 13.8 billion gives 14 billion, which would run the clock backwards right after the label. The schedule rounds to 2 significant figures and then clamps to the range between the two beats, which keeps the ticker monotonic and still stops jitter.
8. **The page-turn act break.** The page turn is detected as "the transition out of the last Act I beat" rather than hard-coding B15, and the schedule test asserts it lands on B15 → B16.
9. **Next 16 specifics** (read in `node_modules/next/dist/docs/`): page `searchParams` is a Promise; `useSearchParams` in a prerendered route must sit inside a `<Suspense>` boundary. The film avoids both: it reads `location.search` once on the client through `useSyncExternalStore` (server snapshot `null`), so `/welcome` stays fully static.

### Found while building L2

10. **The page turn rotates +110°, not −110°.** In CSS a negative `rotateY` swings the free edge toward the viewer; with an 1800px perspective the page balloons to cover the screen and then disappears in about 150 ms, which reads as a flash. A positive angle swings it away and uncovers B16 progressively (see `03-desktop-page-turn-B15-to-B16.jpg`). The value and the reason live in `lib/landing/film-config.ts`.
11. **Reduced-motion crossfades fade only the incoming plate**, on top of the outgoing one, so the frame never dips toward the stage color halfway through.
12. **Header, ticker and control text change color with a 300 ms CSS `color` transition** when the plate's tone flips. Strictly, that's a fourth animated property besides transform, opacity and clip-path; it's three short text runs, and it's what "crossfades in 300 ms" asks for.
13. **Additions for testing:** `?film=reduced` previews the reduced-motion path without changing OS settings, and in development only `window.__film` exposes `schedule()`, `time()`, `freeze(ms)`, `pauseAt(ms)` and `play()` so any frame can be captured exactly (Playwright will use it in L6).
14. **Ticker rounding is coarse between close calendar years.** Two significant figures means 1969 → 1995 shows 1995 straight away, and 1450 → 1492 shows 1492. It never runs backwards, but it barely counts in Act II. Using 3 significant figures for calendar years would let it count; left as the prompt says for now.
15. **GSAP clip-path strings must not end in ".0"** (`81.0px`): the browser reads it back as `81px` and GSAP then snaps instead of tweening. `px()` in `film-timeline.ts` formats without trailing zeros.
16. **Adding dependencies with npm 11.5.1** strips every other platform's optional packages from `package-lock.json` (500+ lines) and breaks vitest's native binding. GSAP was added by merging only its two lockfile entries into the committed lockfile and running `npm ci`. Do the same for `sharp` (L5) and Playwright (L6).

### Found while building L3

17. **`requestStart` lives in `lib/landing/start.ts`**, not `handoff.ts`: it needs the auth client and the login card's store, and `/study` imports `handoff.ts` for the pure URL and storage helpers. `requestStart(h)` keeps the prompt's signature; it navigates with Next's router, which the landing registers through `setNavigator`.
18. **`AuthClient.getSession()` is synchronous** (a cached session), so the header can render from it through `useSession()` (`useSyncExternalStore`). A real client keeps the same shape by caching its session.
19. **"Later" and Esc clear the saved question** from sessionStorage, so it can't surprise the learner on a later visit to `/study`.
20. **The `/study` hint names where the question came from:** "From Starting points · press Enter to begin" (the prompt's text, for `E…` refs), "From the film · …" (`B…` refs) and "From the home page · …" (the final-frame composer).
21. **How `/study` prefills:** `HandoffReader` (inside `<Suspense>`) puts the handoff in a small store (`lib/landing/prefill.ts`) and opens the chat dock if it was collapsed. Every `Composer` remounts keyed on the handoff, starting with the question as its text (`useComposer`'s new `initialText`); the visible one takes focus with the caret at the end. The first send while the handoff waits calls `startLesson(text, level)` and then `sendTurn`, exactly as Home does, so the question gets a fresh lesson and the previous one is archived.
22. **Signed in, the landing header says "Open Chronicle"** (a link to `/study`) instead of "Sign in". The prompt doesn't say; a "Sign in" button for a signed-in visitor would be wrong. The dev badge reads `auth: placeholder · inference: /api/turn`, and offers "sign out" while signed in.

## 6. Plates: from `gen_plates.py` to the film

The first round of 34 plates (FLUX.2 klein on Cloudflare Workers AI) proved the style, but most aren't usable in the film as they are. They are pictures mounted on cream paper with a drawn border; about ten anchors are off-center; they're 1344 px wide (the film wants 1920); several carry fake caption lettering; and B35 doesn't exist yet. Plan:

1. **Round 2 of generation** (runs alongside L1 and L2, free tier): change the pack's GLOBAL STYLE so the scene fills the canvas edge to edge in the beat's own tint, generate natively at 1920 × 1088, and generate B35.
2. **Plate lab (dev only, with L5):** a page that shows each beat's candidates inside the real film chrome (placard, ticker, iris circle). You pick a winner and click its anchor; the import script crops so that point lands at the exact center.
3. **`plates.generated.json` records each plate's measured tone** (dark or light, from the image itself) alongside its files, so the header and ticker colors follow the real image, not only the beat's `bg` tint. This is an addition to the prompt's L5 (open question 3).

## Plays like a video, with a tree timeline (18 Oct 2026)

Owner decision: as a product, a 13-screen scroll story asks too much. The opening should play like a video, and the timeline should be vertical, like a tree (option A: a trunk down the middle, events branching left and right, cause links as branches between them).

- **The opening plays on a clock.**
  - It's one screen tall (`.op { height: 100svh }`). After the 2 s bloom, a GSAP tween drives the same `render(p)` from 0 to 13 over `OPENING_CONFIG.playSeconds` (26 s), then it rests on the landing.

Owner decision, after a research pass: the homepage should look cleaner, the colour schemes were confusing, and the animation should be a small, well-placed part of the page instead of its full width. The research page compares 17 similar products and four directions with live mockups: https://claude.ai/artifact/EVN4B2YJc7p6PA2YLN9ofb. The owner chose **Verdigris with the portrait window**.

- **Look** (`components/landing/landing.css`, `theme.ts`). The tokens live under `.lp`:
  - page `#F1F3EF`, cards white, ink `#16201C`, muted `#5A6660`;
